   分歧，导致 Pydantic v1 工具成功登记却在执行前抛出异常、漏记审计。现在登记时统一生成并
   校验 JSON Schema，执行复用同一份 Schema。公开工具执行与持久审计回归已复现失败并通过修复。

## Spec

1. **P2，已修复**：公开知识发布能力无条件更新来源，同一发布标识的不同问题或答案会覆盖原文，
   违反“相同标识搭配不同业务输入明确返回冲突”。现在知识模块在短事务中保存首次核准内容，
   依靠既有唯一来源键并逐字段核对原输入；原文 pending 和索引 done 均不可被不同输入覆盖。
   普通知识上传和文档更新保留原有更新语义，未修改物理表。公开发布回归覆盖索引失败、重建服务、
   内容冲突、多行字段拼接歧义及相同身份恢复。
2. **P2，已修复**：历史预算计算仍放在 platform，违反“会话模块管理历史投影与摘要预算”。
   现在预算、70%/30% 分层和历史可行性告警全部归 conversation，platform 只校验通用模型容量。

规格轴共 2 项，均已处理；最严重为 P2。
