# ch09 实施计划

1. 复用本地 Langfuse，在图编译后绑定一次 callback；请求元数据携带会话、请求与意图，记录真实模型用量并提供按意图查询。
2. 保存每轮阈值前的召回快照，三个入口统一落池；后台扫描未归并问题，模型标准化并与全部待审问题分批语义查重，幂等记录归并 ID 和次数。
3. 后台提供问题、原话及召回详情；审核使用人工填写的核准答案，复用 ch03 的 MySQL pending → Milvus upsert → done 流程，失败可重试。
4. 使用 ch04 标注集实际召回结果校准多信号 evidence_confidence；知识检索后、Agent 前执行闸。生成自评不足使用既有兜底并落池。
5. 复用 ch04 评估 CLI 与指标，持久化 eval_runs；提供定时运行入口、历史查询和趋势展示，至少实际执行两轮。
6. 逐个后端行为 red → green；前端浏览器验证桌面与移动端；最终提供演示命令、测试结果与开发记录路径。

## 测试边界

拟通过问题池/待审服务、聊天反馈 API、置信度校准接口、评估与用量查询验证验收行为。外部模型、Milvus、Langfuse 使用真实联调验证。测试边界已发送用户确认，确认前只进行调查、文档查证和计划工作。

## 已查证的接口

- LangGraph compile 不接受 callbacks；编译产物支持 Runnable 配置，使用 with_config 绑定。
- SQLAlchemy 当前项目依赖为 >=2.0.55,<2.1；使用异步短事务，网络调用不占事务。
- 知识审核复用 ADR 0002/0003 的原文权威、pending 重放、稳定来源幂等语义。
