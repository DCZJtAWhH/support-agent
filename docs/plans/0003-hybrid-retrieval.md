# 第四章实施与验收计划

需求来源：本次用户完整功能说明；不新增或发布 GitHub 工单。

1. 检索：MySQL 仍为权威源。新增 `knowledge_hybrid_v1` 集合，1024 维 dense + text 原生 BM25，chinese analyzer；两路各 50，Milvus hybrid_search + RRF 合并最多 100，再用 BAAI/bge-reranker-v2-m3 选 10。按 category 先过滤，两路使用同一表达式。旧索引保留，显式重建同步。
2. Query：只看当前问题，模型归一表达并保留型号/数字，检索侧同义扩展；入库一块一份，不做多轮改写或指代消解。
3. 回答：重排后按首尾交错组织证据，引用稳定 chunk id / 来源 / 章节 / 内容摘要。生成阶段结构化自评证据充分性，程序拒绝空证据、低相关、无效引用或自评不足；低置信度以 request_id 幂等落库，保留原话、会话、入口、原因、UTC 时间。禁止承诺到账时间等负面知识进入 System Prompt。
4. 前端：复用现有 UI，通过 SSE sources 帧提供本轮来源快照，编号点击打开来源面板，可跳转原文展示接口。成功回答左下角 👍/👎，选中后显示“已反馈”并锁定，localStorage 仅本地采集。
5. 评估：独立标注集覆盖直接问法、口语、同义词、具体型号、过滤、复合条件与未知问题，标注难度、相关来源章节与答案要点。四策略同一归一问题/语料，报告 Recall@1/5/10/50、MRR、基于逐条事实的模型 Faithfulness、拒答表现，按类型分桶。不用假的数字充当真实模型评估。

已由用户确认的 TDD 边界：检索公开入口；聊天公开入口（含持久化）；评估命令。外部模型 / Milvus 可在边界替身下进行单测，真实服务另做集成演示。逐个纵向切片执行 red → green；前端直接实现并在浏览器验证。
