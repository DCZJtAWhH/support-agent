# 纯对话实现计划

## 状态

2026-11-19：实现与自动化验证已完成，31 项测试通过。模型、base URL、密钥全部经 .env 配置。用户明确纠偏：真实模型验收由用户自行执行，开发过程不访问真实模型；自动化验证只使用模拟上游。正式 spec 按仓库约定记录到 GitHub Issues。

正式 spec：https://github.com/DCZJtAWhH/support-agent/issues/1 。实现与交付命令见根 README.md；阶段验证记录见 docs/dev-notes/0001-pure-chat.md。

## 已确定的设计

- Python + FastAPI + LangChain；直连用户配置的 OpenAI Chat Completions 兼容端点。不得自行替换指定技术。
- 本章只实现纯对话与独立的售后信息提取；无工具调用、Agent 循环。
- 服务端单进程内存保存历史，conversation_id 标识会话；客户端只提交本轮消息及已有会话 ID；重启后会话丢失。
- 使用 PromptTemplate 模板化提示。客服可澄清和收集信息、说明一般流程；订单状态、退款资格、到账时间和赔偿金额需要依据，不得虚构或声称已完成真实操作。
- SSE 收到模型文本增量即推送；不假设一次增量严格对应一个 token。
- 近似 token 预算可配置，预留输出预算；从最早完整轮次开始裁剪，保留 System Prompt 和本轮输入；必留内容仍超限时明确拒绝。
- 售后输出固定为 order_id、request_type、expected_solution。order_id 和 expected_solution 缺失时为 null；request_type 为退款、退货退款、换货、维修、其他、未知。通过 with_structured_output 实现。

## 第二轮已确认的设计

1. 结构化输出方式通过 .env 的 STRUCTURED_OUTPUT_METHOD 选择 json_schema / json_mode，默认 json_schema；显式指定方法，不使用 function_calling。能力不支持时给出清晰错误，不自动切换方式。
2. 单个提取结果表达一份售后描述；多订单或冲突信息无法唯一确定的字段用 null / 未知，不擅自选取订单或诉求。
3. 仅成功完成的对话轮次进入历史；异常或客户端断流的半轮丢弃；同一会话并发请求明确拒绝。SSE 区分会话信息、文本增量、成功结束和错误事件。
4. 测试围绕公开 HTTP 接口和 OpenAI 兼容协议边界，验证流式输出、多轮上下文、会话隔离、预算裁剪、失败回滚及结构化输出错误处理；提供 Prompt 与字段语义的标注评估样例。用户已确认测试边界。开发过程不执行真实模型验收，该部分由用户自行负责。

## 实现阶段补充

- 输出上限参数通过 OUTPUT_TOKEN_PARAMETER 明确选择 max_completion_tokens 或 max_tokens；解决 LangChain 自动改名造成的兼容差异，保留统一 OpenAI 协议，不自动探测或切换。
- 流式响应持续监听断连，覆盖 ASGI 2.0 / 2.4；最终 ASGI body 发送成功后才提交本轮历史，整个响应结束前保持会话互斥。
- 纯 Prompt / 数据资产已完成静态评审和离线标签契约校验；真实模型语义验证按用户要求由其自行负责。

1. 设计收敛：补全 spec、记录最终理解及测试边界；按需记录 ADR，只有存在难以逆转的实质取舍才创建。
2. 文档核查与工程准备：Context7 查明所需 API 的接口定义；解析并锁定兼容依赖；提供 .env.example 和本地运行说明，忽略 .env。
3. 按垂直切片进行 TDD：每次一个 HTTP 可观察行为，先见失败再实现；完成对话流式、会话与预算、售后结构化提取及错误边界。
4. 标注评估：提供信息完整、缺失、歧义、多订单、指令注入和客服越权承诺等样例及人工判据；用模拟上游验证评估管线，真实语义评估由用户自行运行，不以模拟结果冒充模型效果。
5. 评审与交付：检查需求一致性和可维护性，运行必要验证，提供 curl 演示命令、测试结果及 dev-notes 路径。
