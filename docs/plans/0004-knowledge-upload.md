# 聊天页知识上传入口

来源：用户追加要求“请添加前端可以上传文件来添加知识的入口”。

- 界面：聊天页可直接打开“上传知识”对话框。选择一个或多个 UTF-8 `.md` / `.markdown` / `.txt`，每文件最多1 MiB、分块最多200块；显示文件名、大小、上传/处理/成功/失败状态、知识块数量。重复同名文件更新该上传来源，已成功文件不随其他失败重复上传，失败可重试。导入完成后可以直接返回聊天提问。
- 后台：`POST /knowledge/upload` 接收 multipart 的 file 字段。完整验证后才提交原文，使用 `upload:<filename>` 独立来源；复用分块、摘要、pending/done 及固定模型。按上传来源同步，避免上传操作意外处理其他来源的 pending。单进程锁串行化上传写入，不引入任务系统或新数据库表。
- 失败：无效扩展名、名称、UTF-8、空内容及不可切分正文在写库前返回具体提示；索引服务失败返回503，明确原文已保存、索引待重试，同文件重传复用原主键。
- 验证：后端从真实HTTP上传与既有来源/检索入口验证，SQLite和真实仓储，外部 HTTP / Milvus SDK 边界替身，逐个红绿切片；前端直接实现并通过真实浏览器验证桌面/手机、多文件、格式错误、失败重试、导入后问答与引用。持续追加 `dev-notes/ch04.md`，交付演示命令与结果。
