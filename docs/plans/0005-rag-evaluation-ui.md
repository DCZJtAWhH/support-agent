# RAG评估入口与结果页

用户原话：“请在前端增加这个入口。”承接已说明的评估概况、四策略对比、类型/难度筛选、逐题来源与事实依据、重新评估及进度。

1. 聊天页输入框上方加入“RAG评估”，新标签页打开 `/evaluations`，保留当前聊天。结果页复用既有绿白配色，直接呈现保存的真实报告，显示时间、题目数、知识块数、运行模式。
2. 服务端复用 `evaluation.summarize` 计算联合筛选后的指标，表格支持 Recall@1/5/10/50 切换、最优值和相对纯向量变化。逐题呈现标注答案要点、预期来源/拒答、四策略回答、召回排名和原文快照、逐事实Faithfulness依据。无事实时显示N/A，不能把拒答算满分。
3. 从 MySQL 当前生效知识摘要与评估集摘要识别旧报告，明确显示“知识库已更新/评估集已更新”，不能当作最新结果。上传新知识不会自动生成ground-truth题目。
4. 重新评估启动现有真实CLI（同固定技术选型），由单工作进程管理子进程；轮询真实已完成结果数、失败原因与完成状态。报告按运行UUID存放到 `dev-notes/rag-evaluations/`，成功后才切换最新指针，旧章节报告保持不变。重复启动409；失败保留旧结果；服务退出终止自身子进程并记录中断。评估期间知识或标注变化时不发布混合版本结果。
5. 沿用已确认的评估公开边界做后端红绿切片；真实仓储、文件与HTTP接口，进程边界使用独立测试子程序。前端按用户Vibe Coding要求直接实现；浏览器验证桌面/手机、筛选、逐题、来源、真实重新评估和进度。持续追加 `dev-notes/ch04.md`。
